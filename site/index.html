Content index/List your mod

List your mod

Write a listing or a mod pack version for the KSA content index, or change a listing. The page checks the file with the rules of the index while you type.

A listing opens for a change. A pack opens as its next version, with the version raised and the release time set to now, because a pack version cannot change.

What you list

A mod-loader loads other mods. A modpack is a set of listed mods, each at one release, and every version of it is a file of its own. Everything else is a mod.

Releases

Where the index picks up each new release of your mod. It follows the host by itself, and you have to control that host, which the last section explains.

Start here. The page reads the public repository and fills the id, the name, the license and the links from it. Check every value it fills.

The number in the address of your mod on SpaceDock. SpaceDock does not let a web page read its data, so the page fills nothing from it.

Leave it empty and the index picks up your newest release and every release after it. Set a version, such as 1.2, and the watcher also stamps every older release from that version on, with the facts this listing states today, such as the game versions and the dependencies. When an old release needs other facts, correct them with an amendment pull request in content-index-releases. A lower version later stamps more releases, and a higher one removes none.

Select the zip of your latest release. The page reads the file names and the mod.toml in it, and shows the install root and, under Dependencies, the dependencies the index derives. The zip stays on your computer.

About

The folder name your mod installs as, which the game sees, or the name of your pack in the index. 1 to 64 letters, digits, ., _ and -, starting and ending with a letter or digit. It cannot change later.

The name clients show. It can differ from the id.

Display names. Separate several with commas.

One or two sentences for list and search views, at most 280 characters.

Markdown. Show a description image from the Images section with ![alt text](ksa-image:<id>). Clients show no other image, and no HTML.

Preview

An identifier from the SPDX license list, such as MIT or CC-BY-SA-4.0. Join several with AND, or with OR when the user may choose. A license that is not on the list is LicenseRef- followed by a name.

Pack

A pack version goes at packs/<id>/<version>.toml and cannot change after it is merged. A change is a new version.

A SemVer version, such as 1.0.0. It is also the name of the file.

When this version is published, in UTC, such as 2026-09-25T12:00:00Z.

What changed in this version, or the address of a page that says it.

The page says whether the pack id is free, yours, or held by another account, in which case a steward decides. For a free id it writes owner.json from your login and your numeric account id on GitHub.

Members

The listed mods in the pack, each at one release. The page offers the mods of the index and their releases that are not yanked and still download, newest first. A note marks a member with a newer release that is at least as stable as its pin. The pin stays until you move it, and the page offers to move it only when the other pins accept the newer release.

The pack pins every required dependency of its members inside their bounds, and no member conflicts with another. A release that needs a mod that is not listed is marked, because no pack can pin it.

"Add the missing dependencies" pins each required dependency that no member pins, at its newest stable release inside the bounds. When a member needs one of several mods, you choose it.

The forum rules ask a pack thread to list each mod with its version, authors, license, download and thread. The list has one line per member.

Links

Required. The thread of your mod on forums.ahwoo.com. It ties the listing to your forum account and settles a dispute about the id.

The page of your mod on SpaceDock. The mod id above is what the index reads releases from.

Compatibility

Required. The oldest version you know your mod works on, as the game shows it, such as 2026.9.10.5438, or a whole month, such as 2026.9.

Leave it empty unless the mod stops working on newer game builds. Players on a newer build then get a warning before they install. Every release stamped while this is set keeps the limit until you change that release with an amendment pull request.

Platforms known to work (optional)

Leave all off when you know of no platform where the mod fails.

Code mods need a loader. Turn it on and name the loader your mod runs under.

The oldest version below defaults to the newest stable release of that loader.

Leave it empty unless the mod stops working with newer loader versions. Every release stamped while this is set keeps the limit until you change that release with an amendment pull request.

Install and launch

Where a manager puts your loader, and what the player starts. Paths are relative to the install location, with / separators.

A different start on one platform (optional)

Dependencies

Other listed mods yours works with. Code dependencies come from the mod.toml in your release by themselves, so add here only bounds or kinds the release cannot say.

    The dependencies of your mod.toml show here once the index stamps your first release. To see them now, select the zip of your release under Releases.

    Tags

    Pick at least one tag from the list. Clients filter by these. Other tags are allowed, but no client shows them as a filter. A tag is stored as lowercase words joined by -, so Space Station becomes space-station.

    Images

    Images stay on your own host. Select the file so the page can measure it, and give the https address where it is or will be. PNG, JPEG or WebP, not animated.

    Icon

    256 to 1024 pixels on the shorter side, the longer side at most twice the shorter, at most 256 KiB. A square icon of 512 pixels or more is best, because clients show only the square in its center.

    Description images

    At most 16, each at most 2048 pixels per side and 1 MiB. The description shows each with ![alt text](ksa-image:<id>).

    Your listing file

    How the pull request is checked

    1. GitHub asks you to sign in, makes a copy of the index in your account (a fork) and opens its editor. The button copies your file first. GitHub fills in a short new file. For a long one, paste the copy into the empty file. For a change, replace the whole old file with the copy. Several listings can go into one pull request, and it merges by itself once ownership verifies for each of them.
    2. A bot checks the file, downloads your latest release and fetches your images, then comments with its verdict.
    3. It verifies that your GitHub account controls the release host, by one of these:
      • the repository under Releases is in your own account,
      • the repository carries the topic ksa-index-<your-github-username> in lowercase, which is the easy way for an organization repository,
      • the repository has a file .github/ksa-content-index.toml that names the listing id and your username.
      A SpaceDock mod proves it through the source code link on its SpaceDock page. A fork proves it through its owner or the topic only, because it inherits the files of the repository it was forked from. A listing from a fork needs an id of its own.
    4. When everything is green, the pull request merges by itself. Otherwise a steward looks at it.
    1. GitHub asks you to sign in, makes a copy of the index in your account (a fork) and opens its editor at the path of the new version. The button copies your file first. A pack is almost always too long for the link, so paste the copy into the empty file.
    2. The first version of a pack id that main does not have yet is its first claim, which also adds packs/<id>/owner.json with your GitHub login and numeric account id to the same pull request. Open the pull request with the version. The bot answers with a link that adds owner.json to it, and the checks stay red until that file is there. "Check the id" in the Pack section also gives the file. packs/README.md shows it.
    3. A bot checks the files and comments with its verdict, and the checks decide what happens next. The checks of a new GitHub account can wait until a steward starts them. For a later version, choose "Change a listed one" and load the pack. Only the first version adds owner.json.

    Your listing stays in this browser until you open the pull request. Details are in CONTRIBUTING.md.
